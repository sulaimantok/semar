# ADR-0006: Observability Tenancy

- **Status:** Accepted
- **Date:** 2026-10-12

## Context
SEMAR's RBAC is scoped per Project, but exporters know nothing about SEMAR Projects and an embedded Grafana queries its datasources directly. Label filters added by string-manipulating queries are easy to bypass.

## Decision
1. `semar_project`, `semar_provider` and `semar_site` labels are attached **at ingest** (vmagent relabeling / file_sd generated by SEMAR from its Project mappings).
2. Every query (native widgets and Grafana) goes through a **label-enforcing proxy** (`vmauth` / `prom-label-proxy`) based on the user's identity.
3. Logs use **Loki tenants** (`X-Scope-OrgID`) per Project.
4. Grafana uses only proxied datasources; until the proxy is ready, embedded Grafana is limited to Admin/Operator.
5. Workload clusters write metrics with a per-cluster token; the `cluster` label is enforced server-side.

## Consequences
- Project mappings must exist before metrics are opened to non-Admins (Phase 2.5).
- Exit criteria include bypass tests through free-form queries and Grafana.

## Alternatives
- **Backend filtering by appending labels to the query string:** easy to bypass.
- **One observability instance per Project:** strong isolation, but far too much operational load.
